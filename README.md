This project trains a small command parser from labels generated by a larger model. It uses Ollama `phi3.5` as the teacher, fine-tunes `EleutherAI/pythia-70m` as the student, stores datasets and model files in SeaweedFS, and serves predictions through FastAPI on a local k3d Kubernetes cluster.

## API

Send a command to `POST /parse`:

```bash
curl -s http://localhost:8080/parse \
  -H 'content-type: application/json' \
  -d '{"text":"set an alarm for seven thirty am tomorrow"}'
```

The response has exactly four fields:

```json
{"intent":"alarm_set","date":"tomorrow","time":"seven thirty am","place":null}
```

`GET /healthz` checks that the process is running. `GET /readyz` returns 200 once the model is loaded and 503 while it is loading. Responses from `/parse` include `X-Model-Version` and `X-Served-By` headers.

## Run locally

1. Copy `.env.example` to `.env` and set a local SeaweedFS secret.
2. Start Ollama and pull the teacher model when you plan to label data:

   ```bash
   ollama pull phi3.5
   ollama serve
   ```

3. Bring up the cluster and service:

   ```bash
   make up
   ```

`make up` creates the k3d cluster, applies storage and service resources, and attempts to fetch and seed a `v1` model. The service becomes ready only when model files are available. If no model Release asset or local model exists, produce one with the training workflow below and run `make deploy` again.

## Training and evaluation

```bash
make label            # two indexed teacher-labeling workers
make clean-data       # cleaned training data and counts
make train SUBSET=50  # short training check
make train            # full v1 model
make train-v2         # second seed for rollout experiments
make eval             # teacher, base, and student scores
```

For labeling without Kubernetes, use `bash scripts/run_workers_local.sh`. Training writes model files under `models/`; model weights are kept out of the source tree for submission and can be distributed as `v1.tar.gz` and `v2.tar.gz` assets in a GitHub Release tagged `model-v1`.

## Deployment and checks

```bash
make deploy
kubectl -n app get deploy,svc,ingress,hpa,pods
python tools/nacl_sim.py network/nacl.json network/packets_sample.jsonl --check
python scripts/subnet_calc.py
make lint
make test
make load           # requires a running service at localhost:8080
make down           # deletes the local k3d cluster
```

The deployment uses two service replicas, an Ingress, readiness and liveness probes, and a CPU-based HPA. See [the runbook](docs/RUNBOOK.md) for rollout, rollback, recovery, and measurement commands. The [report](report/report.md) explains the architecture and recorded results; `results/` contains the supporting outputs.

## Cost estimate

After measuring requests per second, run:

```bash
python scripts/cost.py --replicas 2 --cpu-limit 1 --mem-gib 1 --rps 8
```

The estimator reads `data/rate_card.json` and reports the indicative cost per 1,000 requests. Replace `8` with the measured rate from your load test.
